# Review workflow v1

A saved review is a human judgement about one candidate under one exact evidence/strategy context. It is not an AI prediction, a verified participant response or automatic approval of a roadmap.

- Actions: accept, defer, override priority. An override assigns High/Medium/Low independently of the computed rank; the calculated score is retained unchanged. A nonblank reason is mandatory for every action. Reviewer labels are self-reported, not authenticated identities.
- Every save appends an event with a UUID, UTC timestamp, opportunity ID and immutable snapshot. Snapshots contain validated original feedback, group assignments/descriptions, resolved accounts, subgroup effort, calculated scores, normalised weights/maxima, confidence, model/settings and source hashes. No synthetic truth labels are included.
- Context identity is the SHA-256 of canonical JSON. Rows are sorted by stable IDs so row order alone does not invalidate a review. Different datasets, assignments, strategy weights, scoring code or settings produce a different context. History from other contexts remains visible as historical and never becomes the current decision automatically. Within a context, show the latest saved event per opportunity, retaining older events.
- Each workspace has an app-generated 256-bit recovery key. Keep it private: anyone holding it can access and add reviews to that workspace. The database stores only its SHA-256 digest. Without the key the app cannot recover or enumerate earlier workspaces. Browser refresh/new sessions require restoring that key. This is lightweight demo isolation, not user-account authentication. Database administrators can read stored data; only use synthetic/nonconfidential input.
- No uploads are persisted until Save review is explicitly selected. Then the snapshot and reason are stored in the configured backend. Exports include evidence snapshots and human reasons, but never the workspace key. Export is for inspection/backup; import/restore from JSON is not implemented.
- Local SQLite defaults to `data/private/reviews.sqlite3` and survives process restarts while that file is retained. Back up the file and recovery key separately. On cloud platforms, set `PRODUCTLENS_DEPLOYMENT=cloud` and `PRODUCTLENS_DATABASE_URL` to a server-side TLS PostgreSQL connection string. Cloud mode requires PostgreSQL and refuses to fall back to local files. PostgreSQL is only claimed verified when its opt-in integration check and hosted restart check actually run.
- Saves are transactional: snapshot and event commit together. Errors are shown without logging the database URL or recovery key. Reruns without a new save do not append records. UI history reads are not globally cached across workspaces.

This records decisions without altering source evidence, model grouping or deterministic scores. Correcting a group's membership or replacing an effort proxy is not implemented by this milestone; record the limitation/reason and defer the candidate where appropriate.
